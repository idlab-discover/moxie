# Common family requirements

Track unresolved needs shared across families. This file does not restrict
family edits or define implemented support; follow [family development](docs/family-development.md)
and the current owner contracts linked below. Check those contracts before
adding a request, merge overlapping requests, and update or remove resolved ones.
Git history retains completed requests and their original evidence.

Each entry records the requesting families, the missing contract, and its shared
owner or reason for common ownership. Link current source or reproducible checks;
keep raw research and measurements in ignored directories. A request alone does
not expand an estimator's authorized scope.

## Open requests

| Families | Missing contract | Ownership and current evidence |
| --- | --- | --- |
| naive_bayes, calibration, other classifiers | A common label-domain trait with associated target type, explicit-class construction, classification validation, encode/decode, class count/equality and accuracy comparison. | [Shared labels](shared/labels/docs/labels.md) supplies encodings but no common classifier-domain trait. The current family adapters are `ClassDomain`, `NumericDomain` and `StringDomain` in [the naive Bayes implementation](src/moxie/_naive_bayes_dense.mojo). [Calibration](docs/calibration/family.md#limits-and-validation) still needs typed classifier labels for #11 part 4. |
| naive_bayes | Boolean targets in shared `encode_column` and `type_of_target`, preserving `[False, True]` classes. | [Shared labels](shared/labels/docs/labels.md) currently accepts Int64, Float32, Float64 and String targets. Boolean categorical feature storage does not supply this target contract. |
| compose, cross_decomposition, discriminant_analysis, dummy, pipeline, model_selection, naive_bayes, isotonic, svm, frozen | Typed per-method metadata requests and routing, including parent-side validation, forwarding and transform_input semantics. | [Moxie](docs/interfaces.md#sample-weight-requests) supplies the fit/score sample-weight request values, resolution, and the provider trait implemented by [isotonic regression](docs/isotonic/api.md#sample-weight-requests). The [LDA and QDA score requests](docs/discriminant_analysis/api.md#score-sample-weight-requests) use that provider with an unset fit request. The [PLS and CCA score requests](docs/cross_decomposition/pls/api.md) use the shared request values. [Naive Bayes](docs/naive_bayes/family.md#sample-weight-requests) exposes fit, score and incremental weight requests. Shared routing for the incremental `classes` argument is still needed. [FrozenEstimator](docs/frozen/api.md#sample-weight-requests) exposes its child's fit and score requests through the provider trait. The six supervised [SVMs](families/svm/docs/api-surface.md#routed-fit-weights-in-multioutput-models) expose the fit/score provider and support routed fit weights in multioutput models. OneClassSVM needs a shared fit-only provider for generic parents. The supervised [Pipeline score overload](docs/pipeline/sequential.md#scoring) routes weights to a requesting final estimator. Composition owners implement forwarding for their remaining entry points. See [Compose scope](docs/compose/scope.md) and [Pipeline](docs/pipeline/sequential.md). |
| svm, model_selection | Resolve scorer names in dense cross-validation and search with the estimator's supported response types. | Model selection owns the [typed scorer interface](families/model_selection/algorithms/validation/docs/scope.md). The [SVC search adapter](families/svm/examples/model_selection_adapter.mojo) uses a typed scorer and provides default stratified folds. Tracked in #3 part 3 and #16 part 2. |
| svm | A common estimator contract for carrying and validating feature names on named dense inputs, including `feature_names_in_`. | Moxie owns the [estimator interface](docs/interfaces.md) and [named table contract](docs/compose/named-columns.md). All five [Naive Bayes classifiers](docs/naive_bayes/family.md#named-dense-inputs) use the named table contract for direct estimator calls. The [SVM scope](families/svm/docs/scope.md) documents explicit feature names on direct dense calls for #16 part 6. [Cross-decomposition](docs/cross_decomposition/README.md#named-dense-inputs) uses the current named table contract for direct estimator calls. |
| svm | Python bindings and estimator reflection. | Moxie owns the [estimator interface](docs/interfaces.md#explicit-mojo-differences). The [SVM scope](families/svm/docs/scope.md) tracks the missing capabilities from #16 part 6. |
| cross_decomposition, discriminant_analysis, isotonic, pipeline | Shared transform output configuration via `set_output`, including a pandas output contract. | Moxie owns the output contract and binding, and [Pipeline](docs/pipeline/sequential.md) owns propagation to its steps. [Cross-decomposition](docs/cross_decomposition/README.md#labeled-projections) exposes typed native tables for the X projection, including paired transforms. [Isotonic regression](docs/isotonic/api.md#labeled-transforms) exposes a typed native table for dense transforms. |
| frozen, pipeline, compose | Sequential slicing and frozen ColumnTransformer indexing for heterogeneous compositions. | Pipeline owns [sequential composition](docs/pipeline/sequential.md). Compose owns [fitted child retrieval](src/moxie/compose/_column_transformer.mojo), which exposes a typed copy through `named_transformers_`. Frozen borrows pipeline steps by [position or name](docs/frozen/api.md#access-to-pipeline-steps). |
| compose, text consumers | Native Python-compatible regex search with explicit syntax errors for `make_column_selector(pattern=)`. | Reusable parsing/matching belongs in shared infrastructure. [Compose](docs/compose/scope.md) currently rejects regex selection; substring matching is not equivalent. |
| compose, preprocessing, impute, feature_extraction | Broader typed input support at each heterogeneous consumer. | [ColumnTable](docs/compose/named-columns.md) routes string, Boolean, Int64, Float32 and Float64 categorical columns through the [shared categorical contract](docs/categorical.md). It also routes raw text to document transformers and gathers Float32, Float64, Int64 and raw Boolean columns into the table's floating dtype for dense consumers. Compose owns table storage and routing, and each consumer owns its typed input support. |
| covariance, general linear-algebra consumers | Evaluate partial-pivoted LU with solve/inverse and signed log determinant for Float32/Float64, both triangles, valid strides and exact-zero-pivot errors. Compare rounding and inverse construction before adoption; do not assume LAPACK parity. | Numerical owner: mojo-linalg and shared adapters. [Shared covariance solves](shared/linalg/docs/linalg.md) are SPD-only. [Covariance parity](families/covariance/docs/parity.md) records remaining near-singular determinant/inverse differences and reproducible audits. |
| impute, kernel_approximation | Float32 polynomial Nystroem normalization and transform parity on ill-conditioned bases, checked through Ridge predictions and IterativeImputer stopping and replay. | Kernel approximation owns the feature map and uses the shared mojo-linalg Jacobi SVD. The [Nystroem numerical contract](docs/kernel_approximation/nystroem/api.md#validation) records cancellation after singular-value clipping. [Iterative composition parity](families/impute/algorithms/iterative/docs/api.md#numerical-implementation-and-validation) covers the passing regimes. The 17-row Float32 gallery-style fixture still diverges with identical basis Gram entries. |
| mixture, model_selection | Allow dense unsupervised search to omit the target argument and use a custom scorer with the shared adapter. | Model selection owns the adapter contract. The [shared dense adapter](families/model_selection/algorithms/search/docs/search.md) provides default estimator scoring with `fit(X, None)`. The [mixture selection notebook](notebooks/mixture/plot_gmm_selection.ipynb) uses it for likelihood scoring and a custom adapter for negative BIC, with the same heterogeneous `Variant[Int, String]` grid. Tracked in #3 part 3 and #24 part 2. |
| pipeline, feature_selection | Allow a dense FeatureUnion to forward typed classifier list targets to supervised branches. | [FeatureUnion](docs/pipeline/feature-union.md) owns branch target dispatch and currently fixes the target to a same-dtype NDArray. `SelectKBest` can consume SVC’s list target through `BuiltinScorer`. The [FeatureUnion gallery](notebooks/pipeline/plot_feature_union.ipynb) exercises the remaining mismatch in #5 part 2. |

## Deferred scope

| Families | Requirement | Scope and ownership |
| --- | --- | --- |
| dummy, sparse composition consumers | Shared CSR/CSC/COO contracts for implicit zeros, validation, shape access, weighted sparse-target counts and sparse predictions; explicit uniform-strategy/output-type behavior. | [Dummy scope](docs/dummy/scope.md) remains dense-only. Existing family-specific sparse support does not authorize these branches.
