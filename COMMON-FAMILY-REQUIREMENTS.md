# Common family requirements

Track unresolved needs shared across families. This file does not restrict
family edits or define implemented support; follow [family development](docs/family-development.md)
and the current owner contracts linked below. Check those contracts before
adding a request, merge overlapping requests, and update or remove resolved ones.
Git history retains completed requests and their original evidence.

Each entry records the requesting families, the missing contract, and its shared
owner or reason for common ownership. Link current source or reproducible checks;
keep raw research and measurements in ignored directories. A request alone does
not expand an estimator's authorized scope.

## Open requests

| Families | Missing contract | Ownership and current evidence |
| --- | --- | --- |
| naive_bayes, other classifiers | A common label-domain trait with associated target type, explicit-class construction, classification validation, encode/decode, class count/equality and accuracy comparison. | [Shared labels](shared/labels/docs/labels.md) supplies encodings but no common classifier-domain trait. The current family adapters are `ClassDomain`, `NumericDomain` and `StringDomain` in [the naive Bayes implementation](src/moxie/_naive_bayes_dense.mojo). |
| naive_bayes | Boolean targets in shared `encode_column` and `type_of_target`, preserving `[False, True]` classes. | [Shared labels](shared/labels/docs/labels.md) currently accepts Int64, Float32, Float64 and String targets. Boolean categorical feature storage does not supply this target contract. |
| naive_bayes, numerical consumers | A shared accuracy policy and validation for scalar Float64 exp/log. | [Naive Bayes](docs/naive_bayes/family.md) and [special functions](shared/special/docs/special.md) use Numax `core.libm`; the [shared numerical policy](shared/numerics/docs/numerics.md) does not yet define scalar exp/log accuracy. Preserve the family numerical evidence when defining the common contract. |
| compose, cross_decomposition, dummy, pipeline, model_selection, naive_bayes, isotonic, svm, frozen | Typed per-method metadata requests and routing, including parent-side validation, forwarding and transform_input semantics. | [Moxie](docs/interfaces.md#sample-weight-requests) supplies the fit/score sample-weight request values and resolution used by [isotonic regression](docs/isotonic/api.md#sample-weight-requests). The [PLS and CCA score requests](docs/cross_decomposition/pls/api.md) use the shared request values. The composition owners implement forwarding. [Compose scope](docs/compose/scope.md) and [Pipeline](docs/pipeline/sequential.md) retain this gap. |
| svm, model_selection | Resolve scorer names in dense cross-validation and search with the estimator's supported response types. | Model selection owns the [typed scorer interface](families/model_selection/algorithms/validation/docs/scope.md). The [SVC search adapter](families/svm/examples/model_selection_adapter.mojo) uses a typed scorer and provides default stratified folds. Tracked in #3 part 3 and #16 part 2. |
| cross_decomposition, naive_bayes, svm | A common estimator contract for carrying and validating feature names on named dense inputs, including `feature_names_in_`. | Moxie owns the [estimator interface](docs/interfaces.md) and [named table contract](docs/compose/named-columns.md). The [Naive Bayes API](docs/naive_bayes/api-surface.md) and [SVM scope](families/svm/docs/scope.md) track the missing capability from #7 part 6 and #16 part 6. The [PLS API](docs/cross_decomposition/pls/api.md) tracks #23 part 6. |
| svm | Python bindings and estimator reflection. | Moxie owns the [estimator interface](docs/interfaces.md#explicit-mojo-differences). The [SVM scope](families/svm/docs/scope.md) tracks the missing capabilities from #16 part 6. |
| cross_decomposition, isotonic, pipeline | Shared transform output configuration via `set_output`, including a pandas output contract. | Moxie owns the output contract and binding, and [Pipeline](docs/pipeline/sequential.md) owns propagation to its steps. |
| isotonic, frozen | Shared estimator tags with one-dimensional input support (`one_d_array`) and a wrapper-specific estimator-check opt-out (`_skip_test`). | Moxie owns the [estimator interface](docs/interfaces.md#explicit-mojo-differences). Isotonic exposes both one-dimensional and one-column input directly. [Frozen](docs/frozen/api.md) forwards native capabilities and needs to inherit the wrapped tags without changing them. |
| frozen, pipeline, compose | Sequential slicing and frozen ColumnTransformer indexing for heterogeneous compositions. | Pipeline owns [sequential composition](docs/pipeline/sequential.md). Compose owns [fitted child retrieval](src/moxie/compose/_column_transformer.mojo), which exposes a typed copy through `named_transformers_`. Frozen borrows pipeline steps by [position or name](docs/frozen/api.md#access-to-pipeline-steps). |
| compose, text consumers | Native Python-compatible regex search with explicit syntax errors for `make_column_selector(pattern=)`. | Reusable parsing/matching belongs in shared infrastructure. [Compose](docs/compose/scope.md) currently rejects regex selection; substring matching is not equivalent. |
| compose, preprocessing, impute, feature_extraction | Broader heterogeneous selection and composition, including raw Boolean features and typed input support at each consumer. | [ColumnTable](docs/compose/named-columns.md) routes string, Boolean, Int64, Float32 and Float64 categorical columns through the [shared categorical contract](docs/categorical.md). It also routes raw text to document transformers and gathers Float32, Float64 and Int64 columns into the table's floating dtype for dense numeric consumers. Compose owns table storage and routing, and each consumer owns its typed input support. |
| covariance, general linear-algebra consumers | Evaluate partial-pivoted LU with solve/inverse and signed log determinant for Float32/Float64, both triangles, valid strides and exact-zero-pivot errors. Compare rounding and inverse construction before adoption; do not assume LAPACK parity. | Numerical owner: mojo-linalg and shared adapters. [Shared covariance solves](shared/linalg/docs/linalg.md) are SPD-only. [Covariance parity](families/covariance/docs/parity.md) records remaining near-singular determinant/inverse differences and reproducible audits. |
| mixture, pipeline | Forward `predict_proba` when an unsupervised final estimator implements `ProbabilityPredictor`. | The [mixture selection notebook](notebooks/mixture/plot_gmm_selection.ipynb) checks `fit`, `predict`, `score_samples`, `score` and `fit_predict` through the shared Pipeline against pinned scikit-learn. It checks probabilities through the fitted mixture on transformed rows. Forwarding is tracked in #21 part 1 and #24 part 1. |
| mixture, model_selection | Support target-free dense search with estimator-default and callable scoring. | Model selection owns the adapter contract. [Dense search](families/model_selection/algorithms/search/docs/search.md) documents the supervised adapter and tagged grid values. The [mixture selection notebook](notebooks/mixture/plot_gmm_selection.ipynb) validates a heterogeneous `Variant[Int, String]` grid and public row selection with a custom adapter that still requires an explicit `None` target. Tracked in #3 part 3 and #24 part 2. |
| ensemble, feature_selection | Support independent fitted copies of dense RandomForest and ExtraTrees estimators. | The ensemble owner manages fitted state in [Forest](src/moxie/ensemble/_forest.mojo) and [ForestEngine](src/moxie/ensemble/_forest_engine.mojo). [SelectionEstimator](src/moxie/feature_selection/_model_importance.mojo) requires `Copyable` for fitted snapshots and a separate configuration clone. Tracked in #5 part 1. |
| pipeline, feature_selection | Allow a dense FeatureUnion to forward typed classifier list targets to supervised branches. | [FeatureUnion](docs/pipeline/feature-union.md) owns branch target dispatch and currently fixes the target to a same-dtype NDArray. `SelectKBest` can consume SVC’s list target through `BuiltinScorer`. The [FeatureUnion gallery](notebooks/pipeline/plot_feature_union.ipynb) exercises the remaining mismatch in #5 part 2. |

## Deferred scope
